IFileStore

interface — 設定ファイルの読み書き抽象 (Read/Write/Exists)。単体テストはインメモリ実装で file IO 非依存にできる (01 の IScriptSource と同じ判断)。Resources の read-only な IVirtualFileSystem とは別 — こちらは設定の永続化 (書き込みあり) 専用の薄い口。

メソッド

名前型説明
Exists(string name) → boolファイルが存在するか。
Read(string name) → string内容を読む。無ければ null。
Write(string name, string content) → void内容を書く (上書き)。

LuxelConfiguration

class — 設定読み込み用の **.NET 標準 IConfiguration** を組み立てるヘルパ。 優先順 (後のプロバイダが勝つ): 設定ファイル (JSON) &lt; 環境変数 &lt; コマンドライン。 これで環境変数 (Section__Key=値) やコマンドライン (--Section:Key=値) が 保存済みファイルを上書きできる (ops による上書きの定石)。 ホスト (LuxelHostBuilder) は Host.CreateApplicationBuilder の IConfiguration (appsettings + env + cmdline) をそのまま読み口にもできる。

メソッド

名前型説明
Build(IFileStore files, string fileName, string envPrefix, string[] commandLineArgs) → IConfiguration設定ファイル + 環境変数 (+ 任意でコマンドライン) をレイヤした IConfiguration を作る。

SettingsStore

class — アプリ設定 (音量・画質・キーバインド等) の永続ストア。String,``0) が Signal`1 を返すのが肝 — 設定画面のコントロール (Slider/Switch/Select) に直結でき、購読側 (音量 → AudioMixer など) も Reactive.Effect で反応できる。値の変更は Signal`1 経由で自動的に内部状態へ反映され、 Save (または AutoSave) でファイルへ書き出す。 ファイル IO 非依存: IFileStore 注入でテストはインメモリに。 壊れたファイル耐性: パース失敗時は既定値で起動し、破損ファイルを .bak に退避する (設定破損でゲームが起動しないのを防ぐ)。

メソッド

名前型説明
LoadFrom(IFileStore files, string name) → SettingsStoreファイルから設定を読み込んでストアを作る。破損 JSON は既定値で起動 + .bak 退避。
LoadFrom(IConfiguration config, IFileStore writeStore, string fileName) → SettingsStore**読み込みは .NET 標準の IConfiguration** から行う (JSON ファイル + 環境変数 + コマンドライン のレイヤ — 後のプロバイダが優先)。 が読み口、 が Save の書き込み先。環境変数などの上書きは config 側で解決され、UI からの変更はファイルへ書き戻る。 String[]) で標準 config を組める。ホストでは LuxelHostBuilder.WithSettings が host の IConfiguration (appsettings+env+cmdline) を使う。
Get(string key, T fallback) → Signal<T>キーに対応する Signal`1 を取得 (初回は登録、以降は同一インスタンス)。 保存済みの値があればそれで、無ければ で初期化する。 値変更は自動で内部状態に反映され、AutoSave なら即保存される。
Save() → void現在の全設定をファイルへ書き出す。
